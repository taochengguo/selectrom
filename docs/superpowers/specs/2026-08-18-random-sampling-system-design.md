# 随机抽样系统设计规格

## 1. 项目目标

构建一个本机可运行的随机抽样系统演示版，由手机端 H5 和电脑端管理后台组成：

- 抽样人员通过手机 H5 接收任务、执行随机抽样并查看个人信息。
- 管理员通过电脑后台创建任务、维护抽样人员和分组、执行人员随机分配、审批重抽并查看任务日志。
- 系统保证人员分配和物资抽样结果随机、不可直接篡改、可追溯。

第一阶段在 Windows 本机运行，使用 MySQL 8。系统应保留迁移到内网或公网服务器的能力。

## 2. 技术架构

系统采用 Django 单体架构，一个 Python 服务同时提供手机 H5、电脑管理后台和业务接口。

### 2.1 技术选型

- 后端：Python、Django。
- 数据库：MySQL 8，通过 Django ORM 访问。
- 页面：Django Templates、Bootstrap、原生 JavaScript。
- 配置：使用 `.env` 保存数据库连接信息和 Django 密钥，并提供 `.env.example`。
- 随机算法：Python `secrets` 与 `secrets.SystemRandom`。

不引入独立前端构建系统，以降低本机安装、启动和维护复杂度。

### 2.2 Django 应用边界

- `accounts`：登录、角色权限、个人资料和密码管理。
- `personnel`：抽样人员档案和人员分组。
- `sampling`：任务、候选物资、人员分配、物资抽样、重抽审批和任务状态。
- `audit`：仅记录抽样任务相关操作。
- `mobile`：抽样人员使用的响应式 H5 页面。
- `management`：管理员使用的电脑端后台页面。

### 2.3 权限边界

- 管理员只能登录电脑管理后台。
- 抽样人员只能登录手机 H5。
- 所有页面和业务接口均在服务端校验角色，不以隐藏菜单代替权限控制。
- 用户密码使用 Django 密码哈希机制保存。
- 系统启用 CSRF 防护、会话安全和服务端表单验证。

## 3. 核心数据模型

### 3.1 用户

字段包括用户名、密码哈希、角色、姓名、手机号、头像、启用状态和时间戳。角色只有管理员和抽样人员两种。

抽样人员可以修改姓名、手机号、头像和密码，不能修改用户名或角色。

### 3.2 抽样人员分组

字段包括分组名称、说明、创建人和时间戳。分组与抽样人员为多对多关系。

管理员负责保证分组成员均可实际承担抽样任务。系统随机分配时不额外排除停用、繁忙、请假或已有任务的成员。

### 3.3 抽样任务

字段包括任务编号、任务名称、指定人员分组、计划时间、需要抽取的物资编号数量、状态、备注、创建人和时间戳。

任务状态包括：

- 草稿：正在录入或导入候选物资。
- 待执行：数据校验通过，等待管理员执行人员分配。
- 待抽样：已分配人员，等待抽样人员开始抽样。
- 进行中：已生成并锁定抽样结果，等待抽样人员确认完成。
- 已完成：抽样人员已确认完成。
- 已取消：管理员取消任务。

### 3.4 候选物资

每行代表一个可被随机抽取的唯一物资编号，字段包括：

- 所属任务。
- 物资编号。
- 订单号。
- 供应商。
- 物资名称。
- 物资数量。

同一任务内物资编号必须唯一。任务的抽取数量必须大于零且不能超过候选物资数量。

任务首次执行后，候选物资、抽取数量和指定人员分组全部冻结，不能再编辑。录入错误需要取消原任务并创建新任务，避免改变已经记录的随机候选范围。

### 3.5 人员分配记录

字段包括所属任务、候选人员快照、选中人员、分配类型、重新分配原因、操作人和时间戳。

- 首次执行只能成功一次。
- 执行时以指定分组在该时刻的全部当前成员作为候选快照，从中等概率随机选中 1 人。
- 重新分配必须由管理员操作并填写原因。
- 一个任务只有一条当前有效分配，历次记录永久保留。

### 3.6 抽样批次与结果

抽样批次字段包括所属任务、版本号、批次类型、重抽原因、审批管理员、审批结果、抽样时间和锁定状态。

抽样结果记录所属批次、被抽中的候选物资和抽中顺序。

- 首次抽样生成后立即锁定，不允许编辑或覆盖。
- 确需重抽时，由管理员批准并填写原因。
- 批准后创建新批次，所有历史批次和结果均保留。

### 3.7 任务审计日志

审计日志只记录抽样任务相关事件，不记录登录、退出或个人资料修改。字段包括任务、操作类型、操作人、变更前后必要数据、IP 地址和时间戳。

记录范围包括：

- 创建、编辑和取消任务。
- 导入、添加、修改和删除候选物资。
- 首次执行和人员随机分配。
- 重新分配人员及原因。
- 首次物资抽样结果。
- 批准或拒绝重抽。
- 重抽结果。
- 完成任务。

进入审计链的数据不做物理删除。需要删除时采用停用、取消或作废语义。

## 4. 核心业务流程

### 4.1 任务创建与物资录入

1. 管理员创建任务，选择抽样人员分组，设置计划时间和抽取数量。
2. 管理员可在后台表格中逐条录入候选物资，也可通过 CSV 批量导入。
3. CSV 和表格字段包括物资编号、订单号、供应商、物资名称和物资数量。
4. 系统校验必填字段、同任务物资编号唯一性、数量合法性和抽取数量上限。
5. 数据全部有效后，任务可进入待执行状态。

CSV 导入采用整批事务：任意行存在错误时整批不写入，并向管理员显示具体错误行和原因。

### 4.2 人员随机分配

1. 管理员在待执行任务上点击“执行”。
2. 系统读取指定人员分组的当前全部成员，并保存候选人员快照。
3. 系统使用 `secrets.choice()` 等概率选中 1 名抽样人员。
4. 系统原子化保存分配记录并将任务更新为待抽样。
5. 任务立即出现在被选中人员 H5 的任务提醒中，并显示未读标记。

普通执行只能成功一次。重复点击或并发请求不能生成多条首次分配记录。

重新分配时，管理员必须填写原因。系统再次从指定分组的当前全部成员中随机选中 1 人，保存新的候选快照和结果，并保留原分配记录。重新分配可以再次选中原人员，因为规则要求对分组全部成员完全随机。

### 4.3 物资编号随机抽样

1. 抽样人员打开分配给自己的待抽样任务详情。
2. 页面显示候选物资数量、需要抽取数量和任务信息。
3. 抽样人员点击“开始抽样”。
4. 服务端在数据库事务中锁定任务记录，并从候选物资 ID 快照中使用 `secrets.SystemRandom().sample()` 无重复抽取指定数量。
5. 服务端原子化保存抽样批次和抽样结果，并将结果锁定。
6. 前端收到已保存结果后，播放物资编号滚动、洗牌、减速和结果卡片依次翻出的动画。
7. 动画结束后显示抽中的物资编号、订单号、供应商、物资名称和物资数量。
8. 抽样人员确认完成后，任务进入已完成状态。

动画只负责展示。随机结果必须由服务端生成和持久化，不能由浏览器决定。刷新、断网或关闭页面不会改变结果；再次进入时直接显示已经锁定的结果。

### 4.4 重抽审批

1. 已产生抽样结果的任务需要重抽时，由管理员在后台直接发起重抽并填写原因。
2. 管理员确认批准后，任务回到待抽样状态，当前有效的人员分配保持不变。
3. 当前分配的抽样人员可以在 H5 创建一个新抽样批次。
4. 新批次仍从该任务候选物资中按相同抽取数量无重复抽取。
5. 原批次和新批次均永久保留，并在任务详情中按版本展示。

## 5. 界面设计

界面沿用“随机抽样 UI”模板的蓝白配色、圆角卡片、轻阴影、渐变主按钮、状态标签、数据概览和清晰导航。

### 5.1 手机 H5

底部固定三个导航页：

- 随机抽样：首页展示当前任务统计、待执行任务和最近抽样记录；任务详情提供“开始抽样”按钮及抽样动画。
- 任务提醒：展示分配给当前人员的待查看、待抽样、进行中和已完成任务，支持状态筛选和未读标记。
- 个人中心：查看和修改姓名、手机号、头像和密码。

页面适配常见手机宽度，主要按钮保持足够大的触控区域，表格信息在手机端转换为卡片显示。

### 5.2 电脑管理后台

后台采用左侧导航、顶部用户区和内容卡片布局，功能包括：

- 工作台：任务总数、待执行、待抽样、进行中和已完成统计。
- 抽样任务：列表、创建、编辑、候选物资录入、CSV 导入、执行、重新分配、重抽审批、结果查看和取消。
- 人员分组：创建分组、编辑说明、添加或移除抽样人员。
- 用户管理：创建管理员或抽样人员、重置密码、启用或停用账号。
- 系统日志：只展示任务日志，可按任务编号、操作类型、操作人和日期筛选。

状态标签颜色约定：待执行为灰色、待抽样为橙色、进行中为蓝色、已完成为绿色、已取消为灰黑色。

## 6. 一致性、并发与异常处理

- 人员分配和物资抽样均使用数据库事务与任务行锁。
- 重复请求、连续点击或多个页面并发操作时，只生成一个有效首次分配或首次抽样批次。
- 分组为空、抽取数量无效、候选物资不足或任务状态不允许时，服务端拒绝操作并返回明确提示。
- 用户无权访问页面或接口时返回登录跳转或 403 响应。
- MySQL 操作失败时回滚整个业务事务，不留下部分分配或部分抽样结果。
- CSV 导入错误包含行号、字段和错误原因，不回显敏感配置。
- 客户端动画异常不影响已经保存的抽样结果。

## 7. 测试策略

### 7.1 单元与业务测试

- 管理员和抽样人员的登录入口及角色权限。
- 任务状态转换和非法状态操作。
- 同任务物资编号唯一性与抽取数量校验。
- 从人员分组全部成员中随机选取 1 人。
- 从候选物资中无重复抽取指定数量。
- 首次分配和首次抽样的幂等性。
- 重新分配原因、历史记录和候选快照。
- 重抽审批、批次版本和历史结果保留。
- 任务审计日志范围，确保不记录非任务操作。

### 7.2 并发与导入测试

- 并发点击执行时只生成一个首次分配。
- 并发点击开始抽样时只生成一个首次批次。
- 正常 CSV、重复编号、字段缺失、非法数量和常见中文编码。

### 7.3 页面测试

- 常见手机宽度下三栏导航、任务卡片、抽样动画和结果页。
- 常见电脑宽度下后台侧边栏、表格、表单和弹窗。
- 未读提醒、状态筛选、错误提示和无数据状态。

## 8. 本机交付与运行

交付物包括：

- Django 完整源代码。
- MySQL 8 建库与账号配置说明。
- `.env.example` 和依赖清单。
- Django 数据库迁移文件。
- 初始化管理员和演示数据的管理命令。
- Windows 启动脚本。
- 示例 CSV 文件。
- 使用说明和默认演示流程。
- 可选 Docker Compose MySQL 配置。

没有 Docker 时，系统可连接本机已安装的 MySQL 8。后续部署到服务器时，只需调整环境变量、静态文件服务和生产运行配置，不改变核心业务模型。

## 9. 第一阶段范围限制

第一阶段不包含短信、邮件、微信或系统推送；任务提醒仅在 H5 站内显示。也不包含单点登录、多租户、复杂排班、请假管理、工作量均衡、电子签名和对外系统集成。

这些能力可在演示版验收后按实际部署需求扩展。
